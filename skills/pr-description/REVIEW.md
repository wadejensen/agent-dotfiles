Re-read each line, paragraph, and section.
For each ask yourself:
* If I deleted this, would the description lose value?
* Has information been repeated in the PR description?
* Could this context be communicated more clearly or directly?
* Does understanding this require the reviewer to have already read the code?
* Does this level of detail _belong_ in a PR description?
* Would this be clearer as a review-guide comment, anchored on the code diff itself instead?
* Can a reader predict the problem and the solution from the title and the
  first two lines alone, without the backstory of this change? If not, tighten the
  opening.
* For every noun your change introduces, can a reviewer who has never seen this PR say what it refers to from the description alone? If not, gloss it in a clause or link it.
